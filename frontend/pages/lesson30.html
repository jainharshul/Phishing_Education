Feature Extraction in Email Security

Feature extraction converts the heterogeneous components of each email into a structured, machine-consumable representation. The process is intentionally multimodal: headers, transport metadata, textual body, HTML DOM, attachments, URLs, and behavioral telemetry are featurized in parallel, then fused. Header parsing yields features such as SPF/DKIM/DMARC outcomes, originating IP and ASN, reverse DNS heuristics, hop-time deltas across Received lines, and alignment indicators (whether the visible From domain aligns with authenticated domains). Transport-level signals include TLS properties, SMTP banner anomalies, and volume-based reputation metrics derived from historical flows.

Text processing is layered and size-aware. Tokenization uses subword tokenizers for transformer ecosystems, complemented by n-gram and lexical features for faster heuristics. Contextual embeddings (fine-tuned BERT-like vectors) represent semantics; additional engineered features capture pragmatic cues: modal verb distributions, request-type flags (credential, payment, link-click), and named-entity matches against corporate registries (executives, vendor names). Textual obfuscation features—Unicode mixed-script rates, zero-width characters, and punctuation anomalies—are calculated alongside entropy and token repetition metrics to flag machine-generated or obfuscated content.

HTML and attachment featurization require separate pipelines. HTML is parsed to DOM graphs; features include counts of interactive elements, script inclusion sources (inline vs external), form action endpoints and their domain alignment, meta refresh occurrences, and suspicious CSS that hides visual indicators. Attachments are fingerprinted via MIME signatures, file-hash reputational lookups, static-file heuristics (PE imports, macros), and, where policy allows, sandbox-execution artifacts (API calls, outbound network connections). URL analysis decomposes links into lexical features (length, tokenization), structural features (subdomain depth, punycode usage), and contextual features (time of registration, WHOIS anonymity, and certificate properties).

Normalization, provenance, and lineage are crucial. Numeric scaling (z-score/min-max), categorical encodings (target or frequency encodings), and sparse hashing strategies preserve numerical stability and reduce dimensionality. Feature lineage metadata ensures traceability for audits and incident investigations: which parse produced a feature, which enrichment service updated the attribute, and the timestamp/version of the featurization logic. Feature selection uses mutual information, model attribution (SHAP values), and cross-validation to prune redundant signals and maintain interpretability. Ultimately, a disciplined feature engineering pipeline produces a high-fidelity matrix that underpins accurate, explainable, and maintainable phishing classifiers.
